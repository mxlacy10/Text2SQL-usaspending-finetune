# AGENTS.md — Text2SQL-usaspending-finetune

Instructions for AI coding agents (Claude Code, Copilot, Codex, Cursor) working in this repo. Read this file before making changes.

## What this project is

A QLoRA fine-tune of a ~7B open model that turns natural-language questions about federal spending into **Spark SQL** over **USAspending.gov** award data stored in **Delta** tables. The fine-tuned model is evaluated against zero-shot, few-shot/schema-RAG, and frontier-model baselines on a held-out test set.

**Main claim:** the fine-tuned 7B model matches or beats few-shot prompting on **execution accuracy**, at a fraction of the cost and latency of a frontier model. Every number in the README has to come from a committed eval run.

Owner: Max Lacy (@mxlacy). This is a public portfolio project. Code quality, reproducibility, and honest reporting matter more than a high score.

## Non-negotiable rules

1. **Never fabricate or hand-edit results.** README tables, charts, and metrics are generated by `scripts/report.py` from MLflow runs or `results/*.json`. If an eval hasn't been run, the README says "not yet run". It never shows a placeholder number.
2. **The test set is frozen.** Don't train on, tune prompts against, or regenerate `data/splits/test.jsonl` after it's created. Use `dev.jsonl` for iteration. Any change to the test set must be a deliberate, documented commit with a new version tag.
3. **No secrets in git.** API keys (OpenAI, Anthropic, Hugging Face, Databricks) come from environment variables or `.env`, which is gitignored. Never print them in logs or notebooks.
4. **No large artifacts in git.** Raw USAspending downloads, Delta tables, model weights, adapters, and checkpoints are gitignored. Adapters go to the Hugging Face Hub or the MLflow model registry, not the repo.
5. **Every generated training pair must execute.** A synthetic question→SQL pair is kept only if its SQL parses, runs against the Delta tables without error, and returns a non-empty result, or an empty result that the question explicitly expects.
6. **Reproducibility.** Seed everything (`SEED=42` in `config/base.yaml`). Pin dependency versions. Each eval run logs the model ID, adapter version, prompt template hash, dataset version, and git commit.

## Stack

- **Python 3.11**, managed with `uv` (`uv sync`, `uv run ...`)
- **PySpark + delta-spark** for ingest and SQL execution. Locally, run Spark in local mode. On Databricks, use the same code against Unity Catalog tables via `config/base.yaml: catalog`.
- **SQL dialect: Spark SQL.** Gold SQL and model outputs are Spark SQL. Don't introduce DuckDB, Postgres, or T-SQL syntax.
- **sqlglot** for parsing and normalizing SQL (exact-match metric, syntax validation).
- **Fine-tuning:** Unsloth + TRL `SFTTrainer`, QLoRA (4-bit). Default base: `Qwen/Qwen2.5-7B-Instruct`. Alternate: `meta-llama/Llama-3.1-8B-Instruct`.
- **Tracking:** MLflow (local `mlruns/` or Databricks-hosted). Log params, metrics, and the adapter as an artifact.
- **Serving:** FastAPI + vLLM or HF `transformers` with the merged adapter.
- **Lint/format/test:** `ruff`, `ruff format`, `mypy --strict` on `src/`, `pytest`.

## Data

- Source: USAspending.gov award data (contracts, grants, and assistance: prime award transactions plus recipient, agency, and location dimensions). Start with a bounded slice, e.g. 2–3 fiscal years, so local Spark stays fast. Record the exact slice in `config/base.yaml`.
- Silver tables use snake_case column names and documented types. `data/schema_card.md` is generated from the silver tables and is the only schema context given to models in prompts.
- Federal **fiscal years** run Oct–Sep. Questions about "FY2024" must filter on the fiscal-year column, not the calendar year. Treat this as a known trap and include it in eval tagging.
- Dollar amounts: use `federal_action_obligation` for obligations unless a question explicitly asks for outlays or total award value. Document every such choice in the schema card.

## Synthetic data generation

- Generate candidates with a frontier model from the schema card plus sample values. Cover these difficulty tags: `single_table`, `aggregation`, `join`, `filter_date_fy`, `top_n`, `nested`, `window`.
- Filter: parse with sqlglot (Spark dialect) → execute → drop errors, drop empty results unless expected, drop near-duplicate questions (normalized text plus embedding similarity), and drop SQL that's semantically duplicated.
- Target 1,500–3,000 kept pairs. Split 80/10/10 **stratified by difficulty tag**. Templates and seed phrasings must not leak across splits.
- Keep a small hand-verified subset (≥100 test items reviewed by a human). Report metrics on it separately as `test_verified`.

## Evaluation

Primary metric: **execution accuracy (EX)**. The predicted SQL's result set equals the gold result set, compared order-insensitively unless the question implies ordering, with float tolerance 1e-6 relative.

Also report:
- exact match after sqlglot normalization
- valid-SQL rate (parses and executes)
- EX broken down by difficulty tag
- p50/p95 latency per query
- cost per 1K queries (tokens × price for API models; GPU-hour estimate for self-hosted)

Baselines, all on the same frozen test set with the same schema card:
1. base model, zero-shot
2. base model, few-shot (k=5) plus schema-RAG
3. frontier model, few-shot (record exact model ID and date)
4. fine-tuned model, zero-shot

Each run writes `results/<run_name>.json` and logs to MLflow. `scripts/report.py` builds the README results table from those files only.

## Commands

```bash
uv sync
uv run python scripts/ingest.py --config config/base.yaml        # USAspending → Delta
uv run python scripts/synth.py  --config config/base.yaml        # generate + filter + split
uv run python scripts/train.py  --config config/train.yaml       # QLoRA (GPU required)
uv run python scripts/eval.py   --config config/eval.yaml --model finetuned
uv run python scripts/report.py                                  # regenerate README results
uv run ruff check . && uv run ruff format --check . && uv run mypy src && uv run pytest
```

Training needs a CUDA GPU. A free Colab or Kaggle T4 works for 7B QLoRA. Everything else should run on a laptop CPU with Spark local mode.

## Coding conventions

- Logic lives in `src/t2s/`. Scripts and notebooks only call into it.
- Type hints everywhere. Use pydantic models for config and for dataset records (`Example(question, sql, tags, split)`).
- Prompt templates are versioned files in `src/t2s/common/prompts/`. Log their hash with every run. Don't inline prompts in code.
- Pure functions for metrics, with unit tests. EX comparison logic must have tests for ordering, NULLs, float tolerance, and duplicate rows.
- Small, focused commits with conventional-commit messages (`feat:`, `fix:`, `eval:`, `data:`, `docs:`).
- Don't add dependencies without a reason in the commit message.

## Definition of done for a change

- `ruff`, `mypy`, and `pytest` pass.
- If the change affects data, splits, prompts, or training, re-run the affected evals and commit the new `results/*.json`.
- The README is regenerated by `report.py` if any results changed. Never edit the table by hand.
- The README's "Limitations" section stays honest: synthetic data bias, single-schema scope, slice of fiscal years, and frontier-generated gold SQL.

## When unsure

Choose the more reproducible, more honest option, and leave a `TODO(max):` comment explaining the decision. Don't silently change the test set, the metric definition, or the dialect.
