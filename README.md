# Text2SQL-usaspending-finetune

QLoRA fine-tune of a ~3B open model that turns natural-language questions about federal spending into **Spark SQL** over **USAspending.gov** award data in **Delta** tables. It's evaluated on **execution accuracy** against zero-shot, few-shot/schema-RAG, and frontier-model baselines.

> Status: pipeline built end to end (ingest → synth → train → eval), with baselines run on both local Spark and Databricks Unity Catalog, plus a Databricks Genie baseline and a secondary LLM-judge metric. The test set is small (see Limitations), so treat the numbers as preliminary.

## Pipeline

```mermaid
flowchart TD
    A[USAspending bulk/API] --> B[Ingest · PySpark]
    B --> C[(Delta tables<br/>bronze → silver)]
    C --> D[Schema card + sample rows]
    D --> E[Frontier LLM generates<br/>question→SQL candidates]
    C -. execute .-> F
    E --> F[Execution filter · dedupe ·<br/>difficulty tagging]
    F --> G[train / dev / test splits<br/>test frozen]
    G -->|train| H[QLoRA fine-tune<br/>mlx-lm · Apple Silicon]
    H --> I[LoRA adapter]
    G -->|test| J
    I --> J[Eval harness:<br/>zero-shot · few-shot/schema-RAG ·<br/>frontier · fine-tuned]
    J --> K[MLflow + results/*.json]
    K --> L[report.py → README results]
    I -.-> M[FastAPI /query · optional]
```

## Approach

1. Ingest a bounded slice of USAspending award data into Delta (bronze → silver) with PySpark.
2. Build a schema card, the only schema context given to models.
3. Generate question→SQL pairs with a frontier model, and keep only pairs whose SQL executes.
4. Stratified train/dev/test splits by difficulty, then freeze the test set.
5. QLoRA fine-tune with `mlx-lm` on Apple Silicon.
6. Evaluate all baselines on the same frozen test set and track runs in MLflow.

See [AGENTS.md](AGENTS.md) for the full spec, rules, and commands.

## Limitations

- Gold SQL is generated by a frontier model and filtered by execution. Only a hand-verified subset is reviewed by a person.
- The local `base_zero_shot` run predates the SQL post-processing fix in `c5d1bdb` (markdown-fence/label stripping), so its 0% is a formatting artifact. The Databricks Unity Catalog re-run above uses the current post-processing.
- Small dataset: 264 kept pairs (210 train / 27 dev / 27 test). With 27 test questions each question moves a score by about 3.7 points, and per-tag cells have n≈3–4, so differences between runs are not statistically meaningful yet.
- The hand-verified `test_verified` subset has not been built yet.
- Cost per 1K queries is not yet measured.
- Single schema (USAspending), one awarding agency (Department of Veterans Affairs), and a limited slice of fiscal years (FY2022–FY2024).
- Synthetic questions may not match how real users phrase things.
- Execution accuracy compares full result sets, so it scores answers with extra or missing columns, aliases, or `DISTINCT` as wrong. The LLM judge is a secondary metric; a human checked only the 16 records where judge and execution accuracy disagreed, not the ones where they agreed.
- The Genie space was configured over three of the four silver tables (no `locations`) and without custom instructions, so its score is not a tuned Genie result. Latencies depend on a Databricks Free Edition workspace and are not production numbers.
- The frontier baseline is re-sampled on each run (local 18/27 vs Unity Catalog 19/27), so its score varies by about a question.
